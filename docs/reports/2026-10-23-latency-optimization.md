## TLS 会话恢复候选

源码提交 `6131f3c9`，来源篡改回归提交 `97d2498`。
`010-sing-box-tls-session-cache.patch` 仅修改固定 sing-box 的标准 TLS 客户端，
每个 outbound 独立创建最多四项的会话缓存。普通 TLS 会话恢复不启用 0-RTT，
不改证书校验、Reality、uTLS、协议注册表、编译标签或现有密码后端。

`build-core.py --tls-session-cache` 显式启用候选，默认与公开发布配方保持关闭。
Go overlay 不改上游树；核心和镜像来源校验重建指定变换，并验证源 SHA、补丁、输出字节及精确 overlay 范围。
原有密码 overlay 的来源和实际指令核对仍保留，未放宽为任意补丁。

在 Rock 的 ARM64 上，对真实构造器执行 TLS 1.2／1.3 首次和恢复握手、独立 outbound 隔离、
错误主机名证书拒绝检查，全部通过。新建 TCP 连接的 TLS 1.3 小样本基准（各 30 次）为：

| 同机服务端＋客户端 | 平均每次 |
| --- | ---: |
| 不使用会话恢复 | 11.03 ms |
| 使用会话恢复 | 3.33 ms |

该基准包含 ARM 同机服务端和客户端，不代表 MT7621 或公网提升；首次连接没有恢复收益，
实际服务器也可能拒绝恢复。首轮测试遗漏生产构建使用的 checklinkname linker 参数而链接失败，
补齐同样参数后通过。12 项核心来源／篡改拒绝检查通过，包括新缓存元数据和生成源码被改时拒绝。
