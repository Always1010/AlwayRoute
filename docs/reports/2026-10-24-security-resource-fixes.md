## 已修复的问题

| 问题与影响 | 修复与验证依据 |
| --- | --- |
| 订阅正文128KiB上限未约束HTTP响应头解析器，恶意来源可能在正文前耗尽内存 | `020-uclient-header-limits.patch` 增加显式 `--header-limits`，解析和分配元数据前限制每个响应16KiB／64行／单行4KiB；包含状态行、空行、折叠和未完成行，跳转按响应计数。真实原生解析器验证上限及正常正文／跳转兼容性。 |
| 初始HTTPS不能阻止后续重定向到明文HTTP | `021-uclient-https-only.patch` 在初始连接及每次跳转建立连接前执行协议策略；订阅默认启用，明确允许HTTP的来源另行处理。真实可信TLS、错误证书及降级测试通过，降级目标没有收到请求。 |
| Windows独立刷机脚本只用chmod不能保证备份私密 | 写入备份前验证完整路径不存在重解析点，设置并读回受保护的当前SID专属DACL；失败拒绝写入。16项检查包含本机真实ACL读回；POSIX权限另行验证。 |
| 构建监督只等待主进程，可能留下忽略TERM的子孙进程 | 在回收主进程前保留其PID／进程组身份，先TERM再有界KILL，确认组内无活动进程；清理不完整明确失败。12项检查包含真实POSIX抗TERM后代。 |
| TProxy复用UDP回写连接失败时丢弃引用而未显式关闭 | 固定上游补丁在清空连接前Close，纳入所有核心构建变体及来源校验。真实回环socket测试通过，去掉修复的负对照稳定复现缺少关闭。 |
| DNS缓存声明512条，但上游实际至少1024条 | 生成配置、检查及说明统一为实际1024条；条数上限不等于字节级内存预算。 |
| 状态RPC同步执行核心／转发查询，慢响应会占用rpcd | 独立后台采样、最多每5秒触发，缓存带revision、进程epoch及有效期；未采到、过期与未知状态明确返回不可用。前端与管理测试覆盖缓存边界。 |
| loopback核心控制接口缺少认证，本机其他进程可操作选择 | 每次实际spawn生成随机临时Bearer，runtime和header为root 0600、目录0700；核心请求从私密文件读取认证头，限制响应头，禁止环境代理和跳转，令牌不进入argv。原生核心验证401、读写选择及重启旧凭据失效。 |
| 新增认证在重复start／respawn与配置提交之间存在时序竞争 | 凭据轮换仅发生在实际spawn包装器中；独立core.lock串行化runtime／header读取、安装和清理，热切换提交重新校验凭据。锁不跨服务重启或就绪等待持有。 |
| 发布流程没有完整运行后端门禁，默认密码实验扩大验证范围 | 发布打包前强制执行真实管理模块／事务、watchdog、forwarding、原生下载器及核心认证；任一失败中止。公开发布默认standard-go，实验密码后端须显式选择，正式来源检查拒绝实验参数。 |

## 验证事实与边界

所有构建主机源码同步先审查rsync dry-run，目标为独立工作副本；没有把整仓库覆盖进现有OpenWrt构建树，没有安装软件、修改主机网络／SSH配置或清空现有缓存。

- 原生uclient在临时目录编译，复用固定源码、已有host libubox及OpenSSL。响应头、TLS、私密头文件权限／链接／FIFO／注入拒绝，以及认证重定向拒绝全部通过。测试服务只使用回环地址与临时端口。
- 真实核心认证使用现有ARM64 host sing-box 1.13.21与生产ucode配置生成模块。无／错令牌返回401，错误PUT不改变选择，正确PUT可回读；重启后旧令牌失效，进程参数不含令牌。没有加载生产节点或监听生产端口。
- CI配方所需libmd／json-c／ucode从锁定归档独立冷编，新解释器真实导入fs／digest并核对SHA256；原构建树未变。详细输入及产物哈希见[冷构建报告](2026-10-24-ci-host-digest-cold-check.md)。这不等于完整GitHub x64 Runner冷构建通过。
- 资源修复已实际增量构建标准Go和既有实验组合两份MIPSLE核心，复用已有工具链与缓存，每份27,918,491字节；标准核心SHA256为 `9764987fd47b72befb74165847da0c1dbabb10569572d6cb0e793d53ae316b39`，实验组合为 `76e839c3df958b71b9c6d1ab718cad9181f24d88cd35f17c911b425e3508b063`。未在MIPS设备执行或刷写；核心文件大小不能代表最终压缩固件大小。
- 本机发布编排6项、设备配方9项检查通过；编排检查真实走失败退出路径，但核心／固件构建部分使用替身。真实manager模块导入、watchdog、10项转发隔离检查及首启权限检查通过。
- 最终修复版本以新冷编ucode执行：84项模型、117项事务、11项订阅下载、11项selection、9项traffic、15项status检查全部通过；重复start隔离行为测试通过。事务覆盖熵／私密写入失败后释放锁、respawn介入热切换以及恢复。前端41项、接口契约17项通过。早期运行曾因fixture的字符串索引、锁模拟及作用域绑定与实际ucode不符而失败，修正替身后重新执行通过，生产权限检查没有被放宽。
- 最后调用当前 `runtime_release_gate()` 完整执行六项门禁，全部通过。测试在新的私有任务目录中用只读用途的路径链接引用现有build_dir、host libubox和新冷编hostpkg；原生下载器仍在临时目录编译。此次实际编排包含上述247项管理检查、init、watchdog、10项forwarding及完整原生下载器／核心认证测试，日志保留在构建主机私有artifacts目录。这是运行时门禁集成结果，不是固件构建或镜像发布结果。
