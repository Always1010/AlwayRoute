## 构建与刷前核验

源码 rsync dry-run 显示 Rock 独立工作副本已经同步；逐文件 SHA-256 将固件输入绑定到本机源码快照。构建树仅有管理包 README 与工作副本不同，先查看该包 rsync dry-run，再同步该文件；四个自有包的输入随后全部一致。复用现有 OpenWrt 构建树、下载、工具链和 Go 缓存，未清空缓存或安装本机依赖。

使用既有 `run-native-build.py` 增量构建，再以 manager profile、原归档基线和显式 `mipsle-asm-r2` 后端运行 `inspect-image.py`。检查覆盖镜像边界与 CRC、设备型号、完整核心来源、包集合、内核载荷和自有文件。相比上一版整机镜像，只有两个管理包的版本变化；核心和其他软件包版本保持。

刷前还将新镜像的自有运行文件与设备当时已通过验证的可写层版本逐文件比较，一致；旧 ROM 中有 5 个文件与新版本不同。一次性 uci-defaults 脚本启动后会被消费，因此只在 ROM 比较中检查其存在和内容，不把它在运行根目录中消失误判为损坏。

- 已核验设备型号、服务状态、保存／应用 revision 一致、没有活动后台事务。
- 37 个文件的配置备份保存在 Rock 私有目录；12 项关键配置、8 个 selector 当前选择另存快照。
- 新镜像复制到路由器 RAM 后 SHA-256 一致，`sysupgrade -T` 返回 0。
- 实际只发送了一次保留配置 `sysupgrade`，未使用 `-n` 清空配置或强制忽略镜像检查。

刷写关闭会话时，SSH 返回 246，输出包含 `ubus ... Connection failed`；随后设备短暂拒绝连接／超时。没有据此重复刷机。新 boot ID `<runtime-id>` 与旧值不同，并核对了 ROM 文件，确认实际升级成功。首启恢复期间 applied revision 曾尚未就绪，等待后自动收敛到 13，无需手动重新应用配置。

- WAN up、双频无线 up；WAN 与 LAN2 均为 1000 Mbps 全双工。
- Rock 有线源地址经 4A 的 UDP／TCP DNS 成功，分别约 0.140／0.004 秒；证书验证开启的透明 HTTPS 返回 204，约 1.663 秒。精确临时主机路由已删除。
