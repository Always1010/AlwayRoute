# 隐私边界与首次公开

本仓库保留项目的提交演进。硬件型号、硬件约束、技术方案、公开上游来源、构建方法和通用网络拓扑可以公开；内网地址本身不是认证秘密。真实订阅地址、代理节点认证信息、设备登录口令、私钥和会话凭证必须留在私有边界。用户名路径、设备运行标识和作者身份应单独评估，不应与口令混为一谈。

## 已检查的边界

2026-10-23 的只读初审覆盖当时 110 个 tracked 文件、全部本地 refs 可达的 68 个提交和 324 个不同 blob。规则初审未发现可确认的真实订阅或节点凭证泄露；这不是“没有秘密”的证明。文档中存在机器用户路径、boot/overlay 运行标识和网络拓扑，需要按公开偏好审阅。补丁中的上游作者署名及邮箱应保留，不能为了匿名化用户而删除上游版权信息。

当时 `.local/`、`artifacts/`、`session-log.md` 及缓存合计有 22,987 个 ignored 文件。`.local/access/4a-luci-login.txt` 是包含实际登录口令的本地私有文件，不得公开。部分 `.local/` 脚本读取或处理认证信息；字段名命中并不能证明硬编码，初审没有完成其全部数据流验证。该目录还可能含退休配置、下载内容及调试证据。

`.gitignore` 只影响默认的新增跟踪行为，不会删除已经提交的历史内容，也不约束 `git add -f`、文件管理器上传、手工 ZIP、Release 附件或固件镜像。发布应从审核过的 Git refs 和明确选取的文件生成，不直接打包整个工作目录。ignored 私有文件仍留在本机，也可能存在于 Rock、旧副本、备份和聊天附件中。

## 离线审查入口

脚本仅使用 Python 标准库和本机 Git，不安装工具、不访问网络、不修改索引、refs 或历史。默认读取 Git 已跟踪文件的当前工作内容，包含尚未提交的修改；不会扫描普通 untracked 或 ignored 文件。新增公开文件必须先明确加入索引，才能纳入默认审查。

在仓库根目录运行：

```powershell
python scripts/audit-public.py
python scripts/audit-public.py --history
python scripts/audit-public.py --history --output .local/public-audit.json
```

`--output` 可选，写入脱敏 JSON，拒绝覆盖已有文件；示例目录必须已经存在。报告不包含匹配值、作者姓名、作者邮箱或完整可疑 URL，只包含位置、类别、计数和作者/提交者身份组数。输出路径建议放在 `.local/`；报告中的文件路径、对象编号和历史结构也可能不适合原样公开。

`--history` 审查所有本地 refs 可达的文本 blob、提交消息以及提交者/作者身份组数，包含 `refs/codex/*` 等辅助 refs。历史 blob 去重扫描，同一 blob 可用于多个提交；输出的 `object` 是对象短编号，不一定是 commit 编号，行号对应该历史内容。身份组数及是否含邮箱仅用于提醒，脚本不替用户选择公开身份，也不改写作者信息。

需要扩大到本仓库可读取的不可达对象时，可另运行：

```powershell
python scripts/audit-public.py --include-unreachable --output .local/public-audit-objects.json
```

该选项隐含 `--history`，通过 `git cat-file --batch-all-objects` 读取对象库中可用对象，可能包含 reflog 保留、失去 refs 或来自已配置共享对象库的内容；它不访问其他设备或其他未关联仓库，也不读取 reflog 文本里的操作者身份和备注。不可达 blob 可能没有可恢复的文件路径，因此报告只给对象编号。树对象、签名、附加 Git 配置和 refs 名称中的隐私不属于文本扫描范围。

2026-10-23 的扩大检查曾发现 refs 可达范围之外约 3.2 万个可用对象，主要是旧第三方源码和工作快照。初始 217 处候选中，35 处为可达历史中的保留前缀测试 UUID，182 处位于 refs 之外；进一步按树路径和测试上下文检查，后者约137处来自上游文档／示例／测试，其余为自有旧测试和预览。测试 UUID 的版本／变体位已纳入占位识别，未按整个测试目录豁免。对象数量会随本地工作快照变化，不能用一次计数声称整个对象库已干净。

已知本地登录口令仅在内存中与不超过2MB的额外文本 blob 做精确子串比较，命中0个对象；这不覆盖大文件、二进制、编码或其他版本。未发现确证需要改写可达提交的认证秘密，未重写提交，也未清空 reflog 或删除应用恢复快照。公开分支正常上传不会包含无引用快照；不要打包或共享整个 `.git/`。本轮环境验证测试的早期提交含一个人工合成的非凭证字面量，会被历史审查报告为候选；应结合 `tests/tools/test_context.py` 的未知字段拒绝测试人工确认，不为消除候选计数而全局豁免该字面量。

规则说明：

- `candidate` 表示需要优先人工确认的候选，包括私钥头、部分服务令牌格式、URL 中的口令或认证查询参数、常见订阅路径及凭证字段中的字面量。候选不是已经确认的泄露。
- `warning` 包括机器用户路径、设备运行标识、内容中的邮箱、完整代理 URI 等需结合上下文审阅的信息。完整代理 URI 可能编码凭证，但本脚本不解码所有协议，因此警告仍可能是真实秘密。
- 只过滤少量明确占位符和本项目保留的全零前缀 fixture UUID，不按 `tests/`、`fixtures/` 路径整体豁免。占位符也可能被误用作真实口令；不应依赖过滤规则保护凭证。
- 退出码 `0` 表示没有强候选，允许存在警告；`1` 表示存在强候选，需处理或人工解释；`2` 表示执行失败。退出码 `0` 不是公开批准或安全证明。终端仅列前 12 个位置，优先显示强候选；完整位置写入可选 JSON。

默认跳过超过 2,000,000 字节的文件/对象、含 NUL 的二进制和当前工作区符号链接，并计数。可通过 `--max-bytes` 调整大小上限。脚本没有专用秘密扫描器的规则覆盖率，不验证凭证是否有效，不解压档案、不解包固件、不解析所有编码/拼接字符串，也不发现所有私人域名、节点名称、照片或个人叙述。应检查跳过项，结合人工审阅；本机缺少专用工具时不自动安装。

## 保留演进节点的历史处理

现有初审没有发现可确认的历史认证秘密，不应仅为内网地址或设备型号无故重写历史。普通公开准备改动可以追加小提交，保留现有演进节点。只在确认历史中有不应公开的内容，或者用户明确决定去除历史身份信息时，才执行经审阅的历史清理。

确需清理时，先建立私有备份和独立清理副本，分别列明要处理的文件内容、提交消息、作者/提交者元数据及 refs 范围。历史改写即使只改一处，也会改变相应提交及后代的哈希；不能同时要求内容改变而原哈希不变。清理工具应配置保留空提交与退化合并节点，例如在经授权且工具已可用时采用 `git filter-repo` 的 `--prune-empty never --prune-degenerate never`，并在执行前审阅其余完整参数和替换规则。

执行后验证旧新提交映射、节点数、父子关系、提交顺序、必要说明和最终文件树；合并拓扑也必须验证。删除敏感文件可能让某些节点变空，但这些节点仍应保留。只在用户选择匿名身份时统一更换本人的作者及提交者姓名/邮箱，不修改上游版权署名。不得把替换映射、原值或含秘密的命令行提交进公开仓库。

只清理分支不能清除其他 refs、reflog、旧对象或其他副本。应分别处理辅助 refs、stash、worktree、reflog、备份以及 Rock 上的旧仓库，并确认这些副本的保留和销毁范围。历史重写和删除本地恢复记录是不同动作，不能未经授权自动清空 reflog 或运行破坏性清理。如果真实认证信息曾被他人获取，应另外轮换对应凭证；历史改写不会撤销已经泄露的凭证。

## GitHub 首次上传流程

以下步骤用于后续人工发布准备；本文和审查脚本均不会 push。远程创建与发布仍按当次明确授权执行。

1. 审阅许可证、上游声明、文档身份信息及准备公开的文件列表；将独立目的分成小提交。明确选择作者公开身份，设置未来身份并不会修改已有提交。
2. 使用 `git status --short`、`git ls-files` 和 `git check-ignore .local/access/4a-luci-login.txt session-log.md artifacts/` 核对边界。不要输出、复制或公开私有文件内容。
3. 对已加入索引的最终内容运行本页离线审查及与改动相称的项目检查。审阅全部强候选、警告和跳过项；需要时再扫不可达对象。完整审查报告留在私有目录。
4. 用 `git for-each-ref --format="%(refname)"` 和 `git log --all --format="%h %s"` 在本机审阅 refs 和演进节点；命令可能显示尚未脱敏的名称或提交标题，不直接贴入公开问题。发布只选择审查过的项目分支，以及明确审查过的标签；不用 `--mirror` 或 `--all` 批量上传辅助 refs。
5. 创建空 GitHub 仓库，避免自动生成另一份 README/许可证后产生无关合并。远程 URL 使用不含令牌的地址；不要把认证令牌写进 Git 配置或命令。只在明确获准发布后，添加远程并显式上传所选分支；先查看 dry-run，再实际发布。
6. 发布后从新克隆复查公开分支、历史、作者身份和文件；核对 Release/Actions/Pages 等另行上传的产物。对镜像及设备备份单独审核，不因源码通过审查就直接公开。
