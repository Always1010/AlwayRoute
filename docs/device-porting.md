# 多设备适配与移植

目标是复用 AlwayRoute 的通用能力，为不同 OpenWrt 设备选择对应构建与验证输入。当前只有 4A 第一版具备项目实机证据，其他设备不得因配置可填写就标记为支持。

## 四层职责

| 层次 | 职责 | 不应混入的内容 |
| --- | --- | --- |
| 通用功能 | LuCI、节点／订阅、模型与 RPC、分流、配置事务、状态、任务调度 | 特定路由器型号和个人主机 |
| 平台与架构 | OpenWrt 依赖、GOARCH、指令集、ELF 身份、可选加密优化 | Flash 分区与 SSH 地址 |
| 设备适配 | target／subtarget／device、seed、镜像格式、分区与容量、设备补丁 | 私钥、PGO 私有路径、个人 LAN 地址 |
| 开发与部署环境 | 构建与缓存路径、连接引用、发流位置、可选首启管理策略 | 放宽设备校验或修改锁定上游版本 |

已有管理、转发及 LuCI 包采用架构无关脚本／资源；仍依赖匹配的 ucode、rpcd、LuCI、firewall4、nft TProxy 和策略路由能力。转发当前读取逻辑 `lan`，多 LAN／VLAN 拓扑需要另外评估，不能据此宣称任意网络拓扑兼容。

配置入口分别为 `firmware/tools/target_profile.py`中的CPU架构、`firmware/devices/`设备配方、`config/environments/`主机角色及[首启部署策略](../config/deployment/README.md)。当前4A原seed与原首启脚本均保留为兼容快照，分别用等价配置和逐字节检查防止漂移。

## 新增目标

1. 确认精确型号、硬件修订、OpenWrt 锁定版本的设备支持、启动／升级镜像格式及可用恢复方式。上游不支持时，单改容量或架构参数不能完成移植。
2. 选择匹配的 CPU 架构，重建 sing-box；禁用不适用的 MIPS 专用 overlay。PGO 与性能数据按架构和负载重新评估。
3. 定义设备 seed、必要补丁、产物路径、设备元数据和镜像检查规则；Flash 总容量与可刷分区分开记录。不同镜像布局需要专用验证器，不复用 4A 偏移计算。
4. 组合通用包选择与设备 seed，在独立构建树审查 `make defconfig` 后的配置；保留有效缓存，不覆盖现有 4A 构建。
5. 检查镜像、核心来源、依赖、权限和管理策略，再按具体授权执行设备部署。
6. 验证启动、认证、配置持久化、DNS／转发、故障回退、升级恢复、内存峰值和代表负载。物理断开构建／辅助主机后验证独立运行，保存带条件的证据。

RAM 容量是运行约束；需要实测订阅更新、并发、规则与统计的峰值。Flash 应保留可写空间，不能仅用“固件小于芯片容量”判断可用。当前 4A 的 DHCP、无 PPP／PPPoE、压缩块和精简诊断选择属于该设备配方，不是通用功能的永久限制。

## 交付与后续工作

当前交付路径为设备专用完整固件。现有四包为未来在兼容 OpenWrt 上安装提供基础；通用软件包发布仍需核心架构绑定、依赖兼容、初次安装及升级验证，尚未作为正式安装方式验收。

实施先明确文档范围，再提取架构／设备配置及检查，最后适配第二个真实目标。第二目标未选定前不虚构设备配置、吞吐或通过状态。由主 Agent 统一维护配置契约和提交；确有独立资料核对或设备验证任务时再安排协作，设备写入保持唯一操作者。

通用开发步骤见[开发流程](development-workflow.md)，当前环境示例见[环境说明](operations/environments.md)，已有设备事实见[设备列表](devices/README.md)。历史报告保留当时主机、拓扑与性能条件，不改写成跨设备结论。
