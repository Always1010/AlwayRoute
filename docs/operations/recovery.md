# 恢复条件与验证边界

已记录的保护包括：外置在线分区备份与校验、配置备份、上一份可用模型、应用失败回退、故障guard、保留配置升级及重启恢复。它们各自有用，但**物理恢复写回尚未实测**，不能宣称完整救砖演练通过。

## 执行前需要具备

- 核对硬件修订、Flash／分区布局、镜像类型和具体哈希；原厂OS1首刷与OpenWrt sysupgrade分别判断。
- 私有外置备份清单可读取、哈希匹配，包含本批需要的网络、无线、认证、主机密钥、marker及管理模型；备份不进入公开仓库或公开产物。
- 有不依赖代理运行的LAN管理通道；核对PC或Rock管理网与上游不重叠，必要物理接线和恢复工具已经具备。
- 明确当前故障属于配置、核心、升级启动、网络还是分区恢复；先选择影响最小且经授权的操作。

## 已知限制

核心整体失败时guard会保守阻断公网TCP／UDP，包括direct规则；LAN管理保留。显式停止或Direct模式属于有意改变运行方式，不能将后台失败自动解释为允许直连。

降级到不支持`policyVersion 2`的旧管理器时，需要匹配的version1配置备份；不能把新版模型直接交给旧后端。恢复出厂会影响网络和认证，不等于回退上一份管理配置。

早期XMiR中断只证明当次步骤未完成；后续降级／root／SSH已有单独报告。当前OpenWrt维护不需要重复漏洞利用。历史备份与主机标识的真实位置在私有资料中，公开报告仅保留类型、校验和与结果。

独立运行、断电和恢复写回的剩余验收见[状态](../status.md)。任何真正的刷写或恢复都应单独核对目标、文件、备份与授权。
