# 构建产物与部署检查

4A用户安装及保留配置升级见[简明刷机指南](../devices/xiaomi-4a-flashing.md)。正式入口 `scripts/flash.py` 默认仅校验本地发布文件和只读设备预检，显式 `--apply` 才备份、暂存及提交一次刷写。以下说明开发联调的阶段边界。

源码同步、编译、设备暂存和设备应用是不同阶段。电脑保存主本，构建主机增量构建；所有产物绑定源码提交、配置、上游锁、包输入与SHA-256。步骤见[开发流程](../development-workflow.md)及[固件说明](../../firmware/README.md)。

## 暂存和复核

`python scripts/device.py --env PATH stage FILE`默认只生成暂存计划，显式增加`--apply`才复制到设备`/tmp/alwayroute-stage-<hash>`并核验哈希；具体参数见`--help`。暂存成功不能推出设备兼容或已部署，不运行sysupgrade、不安装包、不重启服务、不改持久配置。

实际应用前应形成可复核批次：目标设备、产物SHA、对应源码、包／核心来源、镜像检查结果、空间余量、保留配置清单、外置备份与撤回方法。使用镜像检查器不替代设备上`sysupgrade -T`；通过预检也不能替代操作授权和恢复条件。

## 两类升级

- 组件联调：明确覆盖的包或文件、权限、版本与增量空间，先验证隔离检查，再按授权应用；配置失败保持旧模型，不能静默直连。
- 整机保留配置升级：核对持久marker、认证、网络、主机密钥和管理模型备份；按具体批次执行一次升级，等待新系统身份和ROM哈希确认，不因SSH／ubus关闭会话而重复刷写。

原厂OS1首刷与OpenWrt保留配置升级的分区和入口不同，不能复用历史首刷命令。禁止将Bootloader、Factory、ALL或完整设备备份当作普通升级目标。恢复前提见[恢复说明](recovery.md)。

应用后记录版本、ROM／运行文件对应关系、Wi-Fi与LAN管理、实际新连接、DNS／透明转发、配置保留及资源。只报告本轮实际执行的检查，早期负载报告不能当作每轮新镜像重测。
